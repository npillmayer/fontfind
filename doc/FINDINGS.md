These are source-inspection findings; add reproductions before claiming fixes. Keep general fixes in fontfind, not TUI workarounds.

	1. Promise lifecycle, before asynchronous TUI use. Resolve publishes on an unbuffered channel. If FontWithContext returns on cancellation, publication can block forever. A second await after consumption reads a closed channel and can return a zero font with nil error. Define repeatable await semantics, retain the completed result, and make publication independent of waiters. Test cancelled/no waiters, multiple waiters, repeated awaits, and cancellation of resolver work separately. Legacy provider adapters ignore context; wrapping them does not make their underlying I/O cancellable.
	2. Truthful match/fallback results, before automatic substitution. The embedded provider returns success even if no filename matched; its loop retains the last candidate, despite the comment promising the first. System directory search ignores requested weight/style and returned metadata repeats the request. The resolver discards individual provider errors. Add explicit match quality, actual resource metadata, provider provenance, and failure reasons, or a compatible detailed-result API. Do not infer an exact match from nil error or from ScalableFont.Style/Weight alone.
	3. Cache keys and policy isolation. NormalizeFontname merges italic/oblique and several weights, and strips suffixes after a dot. Distinct requests can collide before a custom registry even sees them. Fix key construction upstream with regressions. A per-session registry alone cannot fix this. Provider order and fallback policy also affect results: create a new registry when policy changes or include a policy identity in a detailed cache design.
	4. Resource and provider I/O. Add bounded opening/reading and context-aware providers before remote use. Checking byte length after ReadFontData does not bound its allocation. Audit provider-global state and registry logging with race tests; LogFontList currently iterates its map without locking. Do not assume an isolated registry isolates all provider state.
